# DRCD（別人人工標註的題庫）：事前預測（在跑完整實驗之前寫下）

目的：前面的測試題都是自己（AI）看著文件出的，每份只有 32 題。這次改用 DRCD：台達研究院人工標註的繁體中文題庫。

| 項目 | 內容 |
|---|---|
| 知識庫 | DRCD test 的 378 篇維基百科文章，全部放進同一個索引（約 43 萬字）。每篇文章的段落用空行接回整篇 |
| 題目 | 3,493 題（人工標註，答案中位數 4 個字） |
| 評分 | 取回的前 3 段裡，有沒有一段**涵蓋答案在原文中的位置**（不是只看答案字串，因為只有 66% 的答案在文章裡只出現一次） |
| 文件結構 | 只有文章標題，**沒有章節標題** → 屬於兩步規則的第二步（看上下文增益） |

指令：`python selfcontain.py --auto --data drcd`（結果 `results/selfcontain_auto_drcd_log.txt`）、加 `--labels`（`results/selfcontain_auto_drcd_labels_log.txt`）

| 長度 | 上下文增益：不加標籤 | 正值比例 | 加段首標籤（文章標題） |
|---|---|---|---|
| 32 token | **+0.058** ± 0.025 | 23/40 | +0.038 ± 0.016 |
| 64 token | +0.010 ± 0.016 | 20/40 | +0.003 ± 0.011 |
| 128 token | −0.003 ± 0.010 | 18/40 | −0.008 ± 0.009 |
| 256 token | **−0.018** ± 0.006 | 15/40 | −0.016 ± 0.006 |

規則：選「上下文增益明顯小於 0（超過 2 個標準誤）的最小長度」→ **256 token**。32 token 是正的 → 要切大。

**預測：**（3,493 題時，命中率的標準誤約 0.5～0.7 個百分點，所以用百分點來寫）
1. **32 token 明顯比較差**：token-32 的命中率比最好的 token 長度低 5 個百分點以上。
2. **最好的 token 長度是 128 或 256**（不是 32、64、512），而且規則選的 256 token 和最好的長度差不超過 1 個百分點。
3. **混合檢索有幫助**（問題和文件同語言，結果六）：hybrid-200 比 heading-200 高、hybrid-600 比 baseline 高。

**要誠實記下的事**：寫預測之前，為了確認程式正確，用前 20 篇文章（231 題，約全部的 6%）試跑過 token-32、heading-200、recursive-200、hybrid-200。命中率分別是 81.8%、96.5%、97.8%、98.7%。所以預測 1 的方向已經在小樣本上看過，不算完全盲測；預測 2（最佳長度在哪）和 512 token 的結果沒有看過。
