# 退輔會「常見問答」：事前預測（在跑檢索實驗之前寫下）

目的：驗證結果十四之後修正的**兩步規則**。這份文件是在修正規則之後才選的，屬於第一步「有細章節標題」的文件：123 題 FAQ，每一題都是一個「## 分類｜問題」標題，底下只有那一題的答案。

指令：`python selfcontain.py --auto --data data_faq`（不加標籤）、`python selfcontain.py --auto --labels --data data_faq`（加段首標籤）
結果在 `results/selfcontain_auto_faq_log.txt`、`results/selfcontain_auto_faq_labels_log.txt`

| 長度 | 上下文增益：不加標籤 | 正值比例 | 上下文增益：加段首標籤 | 正值比例 |
|---|---|---|---|---|
| 32 token | **+0.046** ± 0.019 | 24/37 | −0.003 ± 0.010 | 17/37 |
| 64 token | −0.001 ± 0.014 | 14/37 | −0.016 ± 0.007 | 12/37 |
| 128 token | **−0.028** ± 0.009 | 8/37 | −0.027 ± 0.007 | 10/37 |
| 256 token | −0.021 ± 0.010 | 10/37 | −0.017 ± 0.008 | 11/37 |

不加標籤時，32 token 的增益是正的（超過 2 個標準誤），和 RP2040（+0.044）、維基百科（+0.040）差不多：切成 32 token 的答案段落本身看不懂。

**兩步規則的預測：**
1. **加段首標籤（原本的設定 token-32～512）：切小也可以。** token-32 和最好的長度相差不超過 2 題。
2. **不加標籤（token-32-nt～512-nt）：32 token 會失敗。** token-32-nt 比最好的 -nt 長度少 3 題以上（不加標籤時就回到第二步，看增益，增益是正的，所以要切大）。
3. **依標題切加混合檢索（hybrid-600，一段大約就是一題 FAQ）**：命中數不低於最好的 token 設定減 1 題。

如果 1、2 都成立，代表「細章節標題補上了小段落缺少的上下文」在百科之外的第二種文件也成立。如果 1 不成立（加了標籤 32 token 還是明顯變差），兩步規則的第一步就要再修。

另外記下一點：和維基百科不同，這裡加了段首標籤之後，量到的增益從 +0.046 降到 −0.003（維基百科只從 +0.040 降到 +0.027）。這是因為 FAQ 的標題就是問題本身，和使用者的問題很像。這一點只做紀錄，不列入預測。

測試題 `tests_faq.py` 是由另一個看不到任何預測或量測結果的子代理，只看文件內容寫的（32 題加 4 題陷阱題）。
