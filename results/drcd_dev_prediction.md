兩種選法：
- **原本的規則**（增益明顯小於 0、超過 2 個標準誤的最小長度）→ **256 token**（128 的 t = −1.86，差一點）
- **新的選法**（32 token 為正之後，增益平均值第一個 ≤ 0 的長度）→ **128 token**

注意：新的選法在 RP2040 上已經不成立（增益 +0.044 / −0.021 / −0.029，新選法選 64 token，但 64 只有 22/32，最好的 256 有 29/32）。所以這次主要是檢驗 DRCD test 的結果能不能在另一批文章和題目上重現，不是證明新選法通用。

**預測：**（3,524 題；兩個設定的差距用「同一題成對比較」的標準誤，約 0.4 個百分點）
1. **128 token 比 256 token 好**：token-128 − token-256 > 0，而且超過 2 個標準誤（新選法比原本的規則好）。
2. **32 token 明顯比較差**：token-32 比最好的 token 長度低 5 個百分點以上。
3. **混合檢索最好**：hybrid-200 比所有不用混合檢索的設定都高；recursive-200 比 token-128 高。
