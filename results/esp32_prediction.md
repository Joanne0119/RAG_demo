# ESP32-C3 技術規格書：事前預測（在跑檢索實驗之前寫下）

指令：`python selfcontain.py --auto --data data_esp32`（結果在 `results/selfcontain_auto_esp32_log.txt`）
試了 400 個位置，只出到 23 題可用（帶單位的數值大多在表格裡，一行一個值，常常挑不到）。

| 長度 | 上下文增益（平均 ± 標準誤） | 正值比例 |
|---|---|---|
| 32 token | **+0.083** ± 0.018 | 21/23 |
| 64 token | **+0.062** ± 0.015 | 20/23 |
| 128 token | −0.016 ± 0.011 | 10/23 |
| 256 token | −0.013 ± 0.010 | 12/23 |

規則：選「上下文增益明顯小於 0（超過 2 個標準誤）的最小長度」。這份文件沒有任何長度達到 2 個標準誤，
但 32、64 token 明顯為正（和 RP2040 的 32 token 一樣，而且更大），128 token 起才轉為負的。

**預測：ESP32-C3 和 RP2040 一樣要切大。**
1. 32、64 token 的檢索會明顯比 128、256 token 差（預期差 3 題以上）。
2. 最佳長度在 128 token 以上（128～512）。
3. 這份文件是中文，問題也是中文（繁簡不同），所以如果預測成立，「要切大」就不是跨語言造成的。

測試題 `tests_esp32.py` 是在預測跑的同時、還沒看到預測結果前寫的，出題只看規格書內容。
